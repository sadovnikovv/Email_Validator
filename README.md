# Email_Validator (MX + SMTP RCPT) — многопоточная проверка email

Этот проект проверяет email-адреса в несколько этапов:
1) Проверка синтаксиса (библиотека `email-validator`)
2) Проверка домена по DNS (MX-записи)
3) SMTP-проверка доступности получателя (SMTP диалог до `RCPT TO`)

Важно: SMTP-проверка **не даёт 100% гарантии существования ящика** для всех доменов, потому что часть серверов использует catch-all/антиверификацию/временные ответы. 
Статус `valid` в этом проекте означает: “хотя бы один MX вернул 250 на RCPT TO и не было явного permanent-отказа, который однозначно запрещает доставку”. 

## Что есть в проекте

- `smtp_email_checker.py` — основной скрипт (многопоточность, DNS+SMTP, crash-safe сохранение, дружественная финализация). 
- `filters.py` — фильтр “заведомо нецелевых/служебных” адресов (no-reply, postmaster, abuse и т.д.). 
- `filters_config.json` — конфиг фильтров (можно добавлять свои запрещённые local-part до `@`, например `hr`). 
- `rebuild_reports.py` — пересборка Excel-отчётов после падения по `checkpoint.jsonl`/CSV. 
- `requirements.txt` — зависимости. 

## Установка

Требования: Python 3.9+. [code_file:1]

```bash
pip install -r requirements.txt
```


## Входной файл (Excel или CSV)

`INPUT_FILE` может быть:

- Excel: `.xlsx` / `.xls` 
- CSV: `.csv` 


### Заголовок может быть любым или его может не быть

- Если в файле есть заголовок — он может быть любым (например: `Email`, `Значение`, `Почта`, `Contact` и т.п.). 
- Если заголовка нет — первая строка может быть email. 

Программа не привязана к названию колонки: она автоматически ищет колонку, где чаще всего встречаются значения, похожие на email (по шаблону с символом `@`). 

### Разделитель CSV

CSV читается потоково и пытается автоматически определить разделитель (`,`, `;`, таб, `|`). 

## Запуск

Важно: не называйте основной файл `email_validator.py`, чтобы не конфликтовать с пакетом `email-validator`. 

```bash
python smtp_email_checker.py
```


## Результаты (crash-safe)

После запуска создаётся папка:

`results/<YYYY-mm-dd_HH-MM-SS>/` 

Файлы, которые пишутся **во время работы** (append), поэтому при падении прогресс не теряется:

- `checkpoint.jsonl` — 1 строка = 1 результат проверки (удобно для восстановления/аналитики). 
- `valid.csv`, `invalid.csv`, `temporary.csv`, `unknown.csv`, `error.csv` — адреса, разнесённые по статусам. 
- `checked.txt` — список уже обработанных email. 


## Excel-отчёты (опционально)

Создание `.xlsx` может занимать много времени на больших базах, поэтому по умолчанию в коде:

- `BUILD_EXCEL_FILES = False` (Excel отключён). 

Если нужно получить Excel:

- поставьте `BUILD_EXCEL_FILES = True`. 

Также доступна пересборка Excel отдельно после падения/после работы:

```bash
python rebuild_reports.py results/<timestamp>
```


## Фильтрация “нецелевых” адресов

Фильтр позволяет отбрасывать “служебные” ящики и любые адреса по вашим правилам. 
Настройка делается через `filters_config.json`, например: 

- `user_block_local_exact`: `[ "hr", "accounting", "ceo" ]` 


## Настройка производительности

Параметры вверху `smtp_email_checker.py`:

- `NUM_THREADS` — число потоков (скорость vs риск блокировок). 
- `DNS_TIMEOUT_SEC`, `SMTP_TIMEOUT_SEC` — таймауты. 
- `MAX_MX_SERVERS` — сколько MX проверять. 

Рекомендация для очень больших баз:

- оставлять `BUILD_EXCEL_FILES=False` и работать по CSV/JSONL. 


## Правовая заметка

Проверяйте только базы, на обработку которых есть законные основания/согласие.
