# Email_Validator (MX + SMTP RCPT) — многопоточная проверка email

Проект проверяет email-адреса в несколько этапов:
1) Проверка синтаксиса (библиотека `email-validator`)
2) Проверка домена по DNS (MX-записи)
3) SMTP-проверка доступности получателя (SMTP диалог до `RCPT TO`)

Важно: SMTP-проверка **не даёт 100% гарантии существования ящика для всех доменов**, потому что часть серверов использует catch-all/антиверификацию/временные ответы. Статус `valid` означает: “не получили явного отказа (5xx) и хотя бы один MX вернул 250 на RCPT TO”.

## Что есть в проекте

- `smtp_email_checker.py` — основной скрипт (многопоточность, DNS+SMTP, crash-safe сохранение, дружелюбная финализация).
- `filters.py` — фильтр “заведомо нецелевых/служебных” адресов.
- `filters_config.json` — конфиг фильтров (можно добавлять свои запрещённые local-part до `@`, например `hr`).
- `rebuild_reports.py` — пересборка Excel из `checkpoint.jsonl`/CSV после падения.
- `requirements.txt` — зависимости.

## Установка

Требования: Python 3.9+.

```bash
pip install -r requirements.txt
```


## Входные данные

Файл Excel: `emails+1.xlsx`

- Нужен столбец `Email` (или любой столбец, в названии которого есть слово `email`, регистр не важен).
- Пустые значения игнорируются.
- Дубликаты удаляются (с сохранением порядка).


## Запуск

Важно: не называйте основной файл `email_validator.py`, чтобы не конфликтовать с пакетом `email-validator`.

```bash
python smtp_email_checker.py
```


## Выходные файлы и папки

После запуска создаётся папка:

`results/<YYYY-mm-dd_HH-MM-SS>/`

Crash-safe файлы (пишутся **во время** работы):

- `checkpoint.jsonl` — 1 строка = 1 результат проверки (удобно восстанавливать после падения).
- `valid.csv`, `invalid.csv`, `temporary.csv`, `unknown.csv`, `error.csv` — адреса, разнесённые по статусам.
- `checked.txt` — список уже обработанных email.

Excel-файлы (могут создаваться долго на больших базах):

- `01_valid_emails_<ts>.xlsx`
- `02_invalid_emails_<ts>.xlsx`
- `03_temporary_emails_<ts>.xlsx`
- `04_unknown_emails_<ts>.xlsx`
- `05_error_emails_<ts>.xlsx`

Финализация после 100% прогресса:

- Пересборка Excel из CSV
- Создание summary
- Закрытие файлов
В консоли выводится “heartbeat” (крутилка), чтобы было видно, что программа не зависла.


## Восстановление отчётов после падения

Если проверка упала, но в `results/<ts>/` есть `checkpoint.jsonl`, пересоберите отчёты:

```bash
python rebuild_reports.py results/<timestamp>
```


## Настройки (вверху smtp_email_checker.py)

Основные:

- `NUM_THREADS` — число потоков (скорость vs риск блокировок).
- `SMTP_TIMEOUT_SEC`, `DNS_TIMEOUT_SEC` — таймауты.
- `MAX_MX_SERVERS` — сколько MX проверять.
- `FINAL_BUILD_XLSX` — делать ли Excel в конце (если долго, выключите и работайте по CSV/JSONL).
- `REBUILD_XLSX_EVERY_N` — как часто пересобирать Excel в процессе (обычно лучше 0 или большие значения).


## Фильтрация “нецелевых” адресов

Фильтр позволяет:

- отбрасывать `no-reply`, `postmaster`, `abuse`, `unsubscribe` и т.п.
- добавлять свои слова/локальные части до `@` в конфиге

Настройка:
`filters_config.json` → `user_block_local_exact` (например: `["hr", "accounting", "ceo"]`).

## Правовая заметка

Проверяйте только базы, на обработку которых есть законные основания/согласие.
