# Email Validator (MX + SMTP) — многопоточная проверка email

Этот проект проверяет email адреса на уровне:
- синтаксиса (RFC-подобная проверка через `email-validator`),
- наличия MX-записей домена (DNS),
- попытки SMTP-диалога до команды `RCPT TO` (самая “сильная” бесплатная проверка без отправки писем).

## Важно про “100% гарантию”

Нельзя для всех доменов **однозначно** утверждать, что ящик существует, только по SMTP-проверке.
Многие почтовые серверы:
- используют catch-all (принимают любой `RCPT TO`),
- отвечают “250 OK” всегда (анти-верификация),
- применяют greylisting (временные коды 4xx),
- блокируют/троттлят частые проверки.

Поэтому статус `valid` здесь означает: *формат корректный, домен имеет MX и хотя бы один MX в рамках сессии не вернул явную permanent-ошибку на `RCPT TO`*.

## Файлы проекта

- `email_validator.py` — основной скрипт.
- `requirements.txt` — зависимости.
- `results/` — папка результатов (создаётся автоматически, внутри — подпапка с датой/временем запуска).

## Установка

1) Установите Python 3.9+.

2) Установите зависимости:

```bash
pip install -r requirements.txt
```


## Подготовка входного файла

Создайте Excel файл `emails+1.xlsx` со столбцом `Email` (регистр неважен). Пример:


| Email |
| :-- |
| info@company.ru |
| zakaz@company.ru |

## Запуск

```bash
python email_validator.py
```


## Что сохраняется

После запуска создаётся папка:

`results/<YYYY-mm-dd_HH-MM-SS>/`

Внутри:

- `01_valid_emails_<timestamp>.xlsx` — адреса, где минимум один MX вернул `250` на `RCPT TO`.
- `02_invalid_emails_<timestamp>.xlsx` — синтаксис неверный, нет MX или есть явная permanent-ошибка 5xx.
- `03_temporary_emails_<timestamp>.xlsx` — временные ответы SMTP (421/450/451/452) или сетевые проблемы.
- `04_unknown_emails_<timestamp>.xlsx` — неоднозначные случаи.
- `10_detailed_report_<timestamp>.json` — полный отчёт с MX и SMTP-диалогом.
- `00_summary_<timestamp>.txt` — сводка.


## Настройка (вверху `email_validator.py`)

Самые важные параметры:

- `NUM_THREADS` — количество потоков (обычно 5–25).
- `SMTP_TIMEOUT_SEC` — таймаут SMTP.
- `MAX_MX_SERVERS` — сколько MX проверять.
- `JITTER_SEC_RANGE` — небольшая случайная задержка (снижает риск блокировок).
- `RETRY_ON_TEMPORARY`, `RETRY_COUNT`, `RETRY_DELAY_SEC` — повтор при временных ошибках.

Рекомендации:

- Если много таймаутов/отказов — уменьшите `NUM_THREADS` и увеличьте `SMTP_TIMEOUT_SEC`.
- Если всё слишком медленно — увеличьте `NUM_THREADS` (но не слишком, чтобы не словить блокировку).


## Расшифровка SMTP кодов (упрощённо)

- `250` — OK (часто трактуется как “валидно”, но может быть catch-all).
- `421/450/451/452` — временные ошибки (имеет смысл повторить позже).
- `5xx` — постоянные ошибки (обычно “невалидно”).
